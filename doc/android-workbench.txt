1. INTRODUCTION                                 *android-workbench-introduction*

Android Workbench provides a small, native Android project model without
owning Kotlin LSP, formatting, testing, DAP, autosave, or file watching.

The current implementation supports trusted Gradle discovery, root-isolated
state, persistent application/variant/device selection, AVD discovery and
emulator start/stop, Gradle builds, install and launch, application stop,
cancellation, arbitrary registered Gradle tasks, navigable Gradle build errors,
inspectable native task output, and app-scoped Logcat.

==============================================================================
2. SETUP                                               *android-workbench-setup*

Setup is optional and configuration-only. It does not inspect a project, prompt
for trust, create a session, query ADB, enumerate AVDs, or start Gradle.
Built-in adapters use |vim.ui.select()|, |vim.notify()|, |vim.secure.read()|,
and a private JSON state file.

To select with Telescope without changing |vim.ui.select()| globally, run
Gradle through Overseer, retain quickfix as the canonical problem list, and
also project build failures through |vim.diagnostic|: >lua

  require('android_workbench').setup({
    ports = {
      picker = require('android_workbench.integrations.telescope').new(),
      problems = require('android_workbench.integrations.diagnostics').new({
        sink = require('android_workbench.integrations.quickfix').new({
          open_on_failure = true,
          close_on_success = true,
        }),
      }),
      runner = require('android_workbench.integrations.overseer').new(),
    },
  })
<
The explicit example above uses Telescope for selection and Overseer for Gradle
task execution. Overseer opens a non-focused output dock when a task starts,
preserves unseen failed output, and disposes successful output on its normal
timer. Pass `components` to the Overseer adapter constructor to choose a
different presentation policy. Use `:OverseerToggle! bottom` to hide or reopen
the task dock without moving the cursor.

Build, Run, and arbitrary Gradle tasks collect recognized Kotlin, Java, Android
Lint, AAPT, and AGP source errors into one Workbench-owned quickfix list per
project root. The library default populates that list without opening it and
does not publish diagnostics. The example explicitly wraps the quickfix sink in
the optional diagnostic presenter. The quickfix list remains the canonical,
complete collection; the wrapper opens failed lists without moving focus and
closes the matching visible Workbench list after a successful task.

The diagnostic presenter mirrors a failure into a dedicated namespace for its
canonical root and uses an Android Workbench source label. It skips modified
buffers. Editing a projected buffer invalidates its build diagnostics; it is
eligible again only after it is unmodified and a later accepted failure
republishes it. The presenter may create an unloaded buffer handle with
|bufadd()| so native diagnostics appear when that file is opened, but it never
loads or reads the source buffer itself and retains no problem-batch cache.
Namespace and edit-watch state are memory-only and do not survive Neovim
restart. Existing signs, underlines, inline presentation, navigation, detail
views, status components, and a manually opened Trouble diagnostic view can
therefore consume the projection. The presenter never imports or opens Trouble.
Kotlin language-server diagnostics may describe the same compiler error, so
duplicate diagnostic entries are possible.

A successful Gradle task clears only that root's prior Workbench list. With
`close_on_success`, the adapter closes a visible quickfix window only when it
currently displays that exact owned list; it never selects or closes an
unrelated user or plugin list, and quickfix history remains available. A
cancelled task preserves the prior quickfix list and diagnostic projection.
Unrecognized and locationless failures remain in the configured runner output.
The native runner opens a non-focused split below the current window when a
Build, Run, or arbitrary Gradle task starts. Its scratch buffer retains the
latest task for each canonical root, bounded to 10,000 lines and 4 MiB of
combined output. Starting another task for that root replaces the retained
output. Press `q` to hide the split without cancelling the task, `f` to toggle
following its newest line, and use |:Android-output| to reopen it after success
or failure. The window-local bar shows the task, terminal state, root,
truncation, and follow state.

The native output limits and split height can be changed by explicitly
constructing the native runner: >lua

  local runner = require('android_workbench.runner').new({
    max_output_bytes = 4 * 1024 * 1024,
    max_output_lines = 10000,
    height = 12,
  })
  require('android_workbench').setup({
    ports = { runner = runner },
  })
<
An injected custom runner keeps complete ownership of its output UI. In that
case |:Android-output| reports that native output is unavailable; it does not
inspect or replace the custom runner's windows. The Overseer example above
continues to use `:OverseerToggle! bottom`.

Android Workbench defines no global mappings and has no key-hint integration.
Its owned Logcat and native task-output buffers define only their documented
buffer-local controls. A consuming configuration may add mappings to the
commands below and provide native `desc` values for a key-hint UI.

The available ports are `adb`, `emulator`, `runner`, `logcat`, `picker`,
`trust`, `notifications`, `problems`, `state`, and `discovery`. Each is one
explicit adapter table; there is no provider registry or automatic plugin
detection. A shell-free native runner, native Logcat view, native root-keyed
quickfix sink, |vim.ui.select()|, |vim.notify()|, |vim.secure.read()|, private
JSON state, ADB, Android Emulator, and the bundled Gradle provider are used
when their ports are omitted.

During `0.x`, the supported replacement-port contracts are `picker`, `runner`,
`problems`, and `adb`. Their exact DTOs and calling conventions are documented
below and covered by shared conformance fixtures. The `emulator`, `logcat`,
`discovery`, `trust`, `notifications`, and `state` replacement ports are
experimental: they remain explicit setup seams, but their exact custom-adapter
DTOs may change before `1.0`.

Port maturity describes custom replacement contracts, not whether a built-in
workflow works or whether its documented constructor is intentional. Native
defaults and the public facade retain their documented behavior. An
experimental port change will still be recorded in the changelog, but may not
include a compatibility bridge during `0.x`.

General adapter entry points (`start`, `select`, `authorize`, `load`, `save`,
`discover`, `emit`, and `publish`) are called as plain functions. The `adb` and
`emulator` services and returned operation handles use method-style calls with
`self`. Facade callbacks and status calls return owned mutable result and error
data. Changing an earlier result cannot change retained selection, a later
task, or device identity. Operation and Logcat handles retain their identity.

Picker, runner, problem-sink, and ADB adapters have supported `0.x` contracts.
Their named fields and calling conventions will not change without an explicit
compatibility note during pre-release development.

PICKER

`picker.select(request, done)` is a plain-function call. Its request contains
only: >lua

  {
    prompt = 'Android target',
    items = { ... },
    format_item = function(item) return 'display label' end,
    current = ..., -- optional item from the same domain
  }
<
`prompt` is a string, `items` is an array owned by the adapter call, and
`format_item(item)` returns a display string. The optional `current` value
identifies the current candidate. The adapter completes with
`done(error, item)`, where `item` is one supplied candidate; `done(nil, nil)`
is a quiet dismissal. Workbench revalidates the returned identity against its
original candidates, so changing the request or returning a manufactured item
cannot change core state. `select()` may complete before it returns or later,
and may return a method-style cancellable handle.

RUNNER

`runner.start(request, done)` is a plain-function call. Workbench supplies only
these request fields: >lua

  {
    argv = { '/canonical/project/gradlew', '--console=plain', ':app:assembleDebug' },
    cwd = '/canonical/project',
    env = { ANDROID_SERIAL = 'emulator-5554' }, -- optional
    name = 'Android build :app · debug',
    metadata = { ... },
    on_output = function(event) end,
  }
<
`argv` is a non-empty array of direct process arguments; it is never a shell
command. `cwd` and `name` are non-empty strings. Optional `env` is a string
map. `metadata` is an owned table, and `on_output(event)` accepts only
`{ stream = 'stdout'|'stderr', data = string, truncated? = boolean }`.

For Build and Run, metadata contains `kind` (`android-build` or
`android-run`), canonical `root`, `target_id`, `application_id`, and optional
`device_serial`. For an arbitrary Gradle task it contains `kind =
'gradle_task'`, canonical `root`, `task_id`, `build_path`, `project_path`, and
`task_name`. A runner may use these values for presentation, but must execute
the supplied direct argv as given.

The runner completes with `done(error, result)`. A terminal value
contains `status = 'success'|'failure'|'cancelled'` and may contain non-negative
integer `code` and `signal`; string `stdout`, `stderr`, and `error`; boolean
`stdout_truncated`, `stderr_truncated`, and `output_truncated`; and normalized
`problems` plus `problems_truncated`. Native adapters also return `name` and
`metadata`; a custom adapter may omit them because Workbench restores its
canonical request values. Workbench rejects invalid field types, normalizes
problems, and drops unknown result fields. `start()` may complete before it
returns or later, and may return a method-style cancellable handle.

PROBLEM SINK

The supported synchronous problem-sink call is: >lua

  problems.publish({
    root = '/canonical/project',
    kind = 'build', -- or 'run' or 'gradle_task'
    name = 'Android build :app · debug',
    status = 'failure', -- or 'success'
    items = {
      {
        path = '/canonical/project/app/src/main/java/example/Main.kt',
        line = 12,
        column = 7,
        message = 'Unresolved reference: missing',
        severity = 'error',
      },
    },
    truncated = false,
  })
<
`publish(batch)` is a plain-function call and returns `true`, or `nil, error`.
The exact batch fields are `root`, `kind`, `name`, `status`, `items`, and
`truncated`. `root` is a canonical absolute path; `kind` is `build`, `run`, or
`gradle_task`; `name` is a non-empty single-line string of at most 512 bytes;
and `status` is `success` or `failure`. `items` contains at most 1,000 entries.

Each item has an absolute normalized `path` of at most 8,192 bytes, a one-based
`line`, a non-empty single-line `message` of at most 4,096 bytes, and `severity`
of `error`, `warning`, or `info`. Optional `column`, `end_line`, and
`end_column` are also one-based. Position values are integers no greater than
2147483647. Workbench removes duplicate items and sets `truncated` when data
was capped or incomplete.

Empty items replace or clear only the Workbench-owned results for that root.
Reveal and close behavior belongs to the injected sink constructor, not
top-level Workbench setup. Sink failure produces a warning but never replaces
the Build/Run/Gradle-task result. Cancellation and failures before an accepted
Gradle terminal publish nothing.

ADB

The ADB service is a supported `0.x` method-style port with exactly five public
operations: >lua

  adb:list_devices(done)
  adb:validate_serial(serial, done)
  adb:resolve_launch_components(serial, application_id, done)
  adb:launch(serial, application_id, component, done)
  adb:stop(serial, application_id, done)
<
Every method completes with `done(error, value)`, may call it before returning
or later, and may return a method-style cancellable handle. Serial values are
non-empty strings of at most 1,024 bytes without control characters. Spaces
are valid and must be preserved because wireless ADB serials can contain them.
Application IDs are dotted package names of at most 512 bytes. Components are
package/activity pairs of at most 2,048 bytes and must belong to the requested
application ID.

`list_devices()` returns an array of at most 1,024: >lua

  {
    {
      serial = 'adb-example (2)._adb-tls-connect._tcp',
      state = 'online',
      raw_state = 'device', -- optional
      label = 'Pixel 10 Pro', -- optional
      details = '...', -- optional
    },
  }
<
`state` is `online`, `authorizing`, `bootloader`, `connecting`, `detached`,
`host`, `offline`, `recovery`, `rescue`, `sideload`, `unauthorized`,
`no_permissions`, or `unknown`. `validate_serial()` returns the same device DTO
for that exact serial only when it is online; a running emulator also includes
its stable `avd_name`.

`resolve_launch_components()` returns at most 1,024 exact component DTOs: >lua

  {
    {
      component = 'com.example.app/.MainActivity',
      package = 'com.example.app',
      activity = 'com.example.app.MainActivity', -- optional
    },
  }
<
The list is normalized and contains no duplicate component identities.
`launch()` returns: >lua

  {
    serial = 'emulator-5554',
    application_id = 'com.example.app',
    component = 'com.example.app/.MainActivity',
    status = 'ok',
    activity = 'com.example.app/.MainActivity', -- optional
    launch_state = 'COLD', -- optional
    total_time_ms = 312, -- optional
    wait_time_ms = 340, -- optional
  }
<
The status is case-insensitive `ok`; optional times are non-negative bounded
integers. `stop()` returns only the exact stopped identity: >lua

  { serial = 'emulator-5554', application_id = 'com.example.app' }
<
Workbench revalidates component, launch, and stop identities. A custom
adapter's extra launch or stop fields do not widen the public Run or Stop
result.

The native ADB implementation has additional private capabilities. Native
Logcat needs synchronous executable resolution. When a custom ADB service is
combined with native Logcat, it must also implement `resolve_executable()` or
setup fails. Native emulator start additionally uses `resolve_avd_name()` and
`boot_completed()`; native emulator stop uses `resolve_avd_name()` and
`kill_emulator()`. Those helpers are not part of the five-method public ADB
service. Pair a custom ADB service with custom Logcat and emulator adapters
unless it deliberately implements the matching native-private capabilities.
Missing emulator capabilities fail that lifecycle operation with
`unsupported_adb_service`.

The experimental emulator replacement port currently has these asynchronous
methods: >lua

  emulator:list_avds(done)
  emulator:start(avd_name, done)
  emulator:stop({ avd_name = avd_name, serial = serial }, done)
<
Completion callbacks use `(error, value)` and may run synchronously. Each method
may return a cancellable handle while work remains. AVD list items contain an
`avd_name` and optional presentation fields. Start returns the exact online
device identity, including `serial`, `avd_name`, and `state`. Stop is always
scoped to both the remembered AVD name and its current ADB serial.

By default, Run starts a remembered stopped AVD and waits for it to become
ready without opening another picker. To require an explicit emulator start: >lua

  require('android_workbench').setup({
    run = { start_stopped_avd = false },
  })
<
The native lifecycle uses a three-minute boot timeout and one-second readiness
poll. Both values are configurable positive integers in milliseconds, bounded
at 2147483647: >lua

  require('android_workbench').setup({
    emulator = {
      boot_timeout_ms = 180000,
      poll_interval_ms = 1000,
    },
  })
<
An explicit native executable path is configured on the adapter constructor,
not as a broad Workbench option: >lua

  local adb = require('android_workbench.android.adb').new()
  local emulator = require('android_workbench.android.emulator').new({
    adb = adb,
    emulator = '/opt/android-sdk/emulator/emulator',
  })
  require('android_workbench').setup({
    ports = { adb = adb, emulator = emulator },
  })
<
A different command-line flag policy belongs in a custom emulator adapter.

Logcat does not open automatically after Run unless requested: >lua

  require('android_workbench').setup({
    logcat = { open_on_run = true },
  })
<
The native presenter can be replaced as `ports.logcat`, or configured directly
before injection: >lua

  local logcat = require('android_workbench.logcat.native').new({
    max_records = 20000,
    max_line_bytes = 64 * 1024,
    max_retained_bytes = 4 * 1024 * 1024,
    height = 18,
  })
  require('android_workbench').setup({
    ports = { logcat = logcat },
  })
<
The port has one `start(request)` method and returns a handle with `show()` and
`stop()`. The request contains neutral project, application, and device data,
plus an optional lazy `resolve_adb()` function. Custom presenters can ignore
the resolver and do not receive native-buffer details.

The native defaults retain at most 10,000 records and 4 MiB of raw record text.
A logical line is limited to 64 KiB. A longer line is discarded through its
next newline before parsing resumes, including when it spans output chunks.
The byte limits measure Lua string bytes. Oldest records are evicted first when
either history limit is exceeded.

The default Gradle provider can be constructed with a project-specific
configuration-cache policy or timeout: >lua

  local discovery = require('android_workbench.gradle.discovery').new({
    configuration_cache = false,
    timeout_ms = 600000,
  })
<
Pass that adapter as `ports.discovery`. Use `timeout_ms = false` to disable the
default five-minute timeout. Omitting `configuration_cache` respects the
project's own Gradle policy; `true` or `false` explicitly overrides it. A
custom discovery adapter may also provide `is_stale(snapshot)`. Without that
method, Workbench conservatively discovers again for each model-dependent
action instead of caching an unverifiable snapshot. A successful custom
snapshot must use `schema_version = 1`, return the exact requested canonical
`root`, and provide bounded plain arrays named `builds`, `targets`, and `tasks`.
Their records are closed DTOs: build, target, project, and task identities must
be exact and unique; target task names and all cross-collection references must
agree. Every task is exactly `{ id, build_path, project_path, name }`, with `id`
matching the derived qualified Gradle identity. Workbench validates and copies
the complete snapshot before caching it. It also passes an owned copy to
`is_stale(snapshot)`, so later adapter mutation cannot change the cached model.
Malformed, partial, aliased, or identity-inconsistent results are rejected.

3. LUA API                                               *android-workbench-api*

The supported pre-1.0 Lua facade is returned by: >lua

  local android = require('android_workbench')
<
Its public functions are listed below. `setup()` is optional, validates and
stores configuration only, and returns no value. Invalid setup options,
contexts, callbacks, or target kinds are programmer errors and throw before an
Android action starts.

                                                   *android-workbench.setup()*
  android.setup(opts)

                                              *android-workbench.is_project()*
  under_root = android.is_project(context)

                                             *android-workbench.open_actions()*
  handle = android.open_actions(context)

                                                   *android-workbench.status()*
                                              *android-workbench.show_status()*
  status, err = android.status(context)
  status, err = android.show_status(context)

                                                  *android-workbench.refresh()*
                                            *android-workbench.select_target()*
                                                    *android-workbench.build()*
                                                      *android-workbench.run()*
                                              *android-workbench.gradle_task()*
                                           *android-workbench.start_emulator()*
                                            *android-workbench.stop_emulator()*
                                                     *android-workbench.stop()*
                                                   *android-workbench.logcat()*
  handle = android.refresh(context, callback)
  handle = android.select_target(kind, context, callback)
  handle = android.build(context, callback)
  handle = android.run(context, callback)
  handle = android.gradle_task(context, callback)
  handle = android.start_emulator(context, callback)
  handle = android.stop_emulator(context, callback)
  handle = android.stop(context, callback)
  handle = android.logcat(context, callback)

                                         *android-workbench.show_task_output()*
                                             *android-workbench.stop_logcat()*
                                                  *android-workbench.cancel()*
  shown, err = android.show_task_output(context)
  stopped, err = android.stop_logcat(context)
  cancelled, err = android.cancel(context)

                                                *android-workbench.shutdown()*
  android.shutdown()

`kind` for `select_target()` is `app`, `variant`, or `device`. Callbacks are
optional; command users normally omit them.

CONTEXT

Every root-aware facade function accepts `nil` or a context containing only: >lua

  {
    bufnr = 0,                  -- non-negative buffer number
    path = '/project/Main.kt', -- non-empty path
    root = '/project',         -- non-empty root hint
  }
<
All fields are optional. `root` takes precedence over `path`, which takes
precedence over `bufnr`. Without `path`, Workbench uses the named buffer path,
then the current working directory for an unnamed buffer. The value is still a
root-discovery input: Workbench resolves and canonicalizes the directory that
owns `gradlew` rather than trusting a caller-supplied canonical identity.

`is_project()` returns `true` when that context is below a directory containing
`gradlew`, and `false` when no wrapper can be resolved or the path cannot be
inspected. It does not prove that the Gradle build contains an Android target;
that requires trusted Gradle discovery. The query only reads the filesystem.
It does not construct the application, load Workbench state, prompt for trust,
run Gradle, query ADB, or enumerate AVDs. Consumers may use it for contextual
buffer-local policy without depending on the private root resolver.

CALLBACKS AND HANDLES

Async callbacks use `callback(error, result)`. They may run synchronously
before the facade function returns or later on Neovim's main loop. A live
operation reaches its callback exactly once. On operational failure, `error`
is present and `result` is `nil`. A successful picker dismissal may return
`nil, nil` because no action was selected.

Async facade functions return a handle with method-style `handle:cancel()`.
It returns `true` when cancellation is accepted and `false` after terminal
completion or when the current child refuses cancellation. Acceptance does not
mean the child has exited yet; the callback arrives when the owned terminal is
accepted. |android-workbench.cancel()| applies the same rule to the current
root operation.

|android-workbench.shutdown()| is the deliberate exception to terminal callback
delivery. It irreversibly revokes the current application instance, closes its
owned views and sessions, attempts child cancellation, and suppresses every
pending public callback and late outward side effect. A later facade action
constructs a fresh independent instance. `setup()` may configure that new
instance before its first action.

RESULTS

`status()` and successful refresh/selection callbacks return: >lua

  {
    root = '/canonical/project',
    wrapper = '/canonical/project/gradlew',
    phase = 'idle', -- idle, discovering, ready, or error
    authorized = false,
    targets = 0,
    selection = {
      app = { build_path = ':', project_path = ':app' }, -- optional
      variant = 'debug',                                -- optional
      device = { serial = '...', avd_name = '...' },    -- optional
    },
    operation = nil,
    logcat = 'stopped', -- stopped, starting, or running
    task_output = false,
    error = nil,
  }
<
Successful action results guarantee these fields:

  build          `{ kind = 'build', target, task }`
  run            `{ kind = 'run', target, device, component, task }`
  gradle_task    `{ kind = 'gradle_task', gradle_task, task }`
  stop           `{ kind = 'stop', target, device }`
  start_emulator `{ kind = 'emulator_start', device }`
  stop_emulator  `{ kind = 'emulator_stop', device }`
  logcat         `{ kind = 'logcat', target, device, handle }`

A target includes `id`, `build_path`, `build_root`, `project_path`,
`project_dir`, `variant`, `application_id`, `assemble_task`, and optional
`install_task`. A device includes its stable available identity: `serial`,
optional `avd_name`, and optional `state`. A Gradle task includes `id`,
`build_path`, `project_path`, and `name`. A launcher component includes
`component`, `package`, and optional `activity`. The Logcat result handle
supports method-style `handle:show(opts)` and `handle:stop()`.

The nested task terminal guarantees `status`, `name`, `metadata`, `problems`,
and `problems_truncated`, with optional `code`, `signal`, bounded `stdout` and
`stderr`, and matching truncation flags when the runner supplies them. Unknown
adapter-specific runner fields are removed before this result crosses the
facade.

All mutable status, result, and error data belongs to the caller. Mutation
cannot change cached selection, a later task, or another result. Operation and
Logcat handles deliberately retain identity; call their documented methods
instead of copying or mutating them.

ERRORS

Operational failures returned synchronously or through a callback are closed
owned tables: >lua

  {
    code = 'project_not_trusted',
    message = 'Android project execution was not authorized.',
    root = '/canonical/project', -- optional
    details = {},                -- optional, action-specific and opaque
  }
<
`code` is the machine-readable classification and `message` is the user-facing
explanation. `root` is present when a canonical project is known. `details` is
owned but has no general schema; do not parse it unless a specific workflow
documents its contents. Unexpected adapter strings, exceptions, or malformed
errors become `operation_failed` instead of escaping as another public shape.

MODULES

The facade above and the `android_workbench.health` entry used by
`:checkhealth` are intentional. These constructor modules are also explicit
pre-1.0 entry points because their constructors are documented in Setup:

  android_workbench.runner
  android_workbench.android.adb
  android_workbench.android.emulator
  android_workbench.gradle.discovery
  android_workbench.logcat.native
  android_workbench.integrations.telescope
  android_workbench.integrations.overseer
  android_workbench.integrations.quickfix
  android_workbench.integrations.diagnostics

Constructor-module intent does not promote an experimental replacement port.
`app`, `session`, `root`, `device`, `execution`, `config`, `command`, `actions`,
`notify`, `state`, `task_operation`, Gradle model/task helpers, and
Logcat/problem models are private implementation modules. Lua can `require()`
them, but reachability is not a support promise.

==============================================================================
4. COMMANDS                                          *android-workbench-commands*

                                                     *:Android*
:Android
        Open a flat searchable list of actions using the configured picker.
        Entries reflect cached selection and active-operation state. Opening
        the list does not authorize the project, run Gradle, query ADB,
        enumerate AVDs, or start another workflow.

        If another plugin or the user's configuration already defined the
        global `:Android` command before Android Workbench loads, Workbench
        leaves that command unchanged and emits one warning. It does not
        replace the incumbent command.

:Android status
        Show the current root, discovery phase, authorization state, target
        count, selected application, variant, device, and active operation.
        This never runs Gradle, queries ADB, enumerates AVDs, or prompts for
        trust. A remembered stopped AVD is shown by name without probing it.

:Android refresh
        Authorize the project if needed, then replace the cached model only
        after a complete Gradle discovery succeeds.

:Android target app
        Select and persist an Android application project. Discovery is lazy.

:Android target variant
        Select and persist a variant for the current application.

:Android target device
        Open one picker containing connected physical devices, running
        emulators, and stopped AVDs. Selecting a stopped AVD remembers it but
        does not start it. A running emulator is identified by both its ADB
        serial and AVD name so a reused console port cannot silently select
        another AVD. Physical devices must already be online in ADB; Workbench
        preserves wireless ADB serials containing spaces exactly but does not
        pair, authorize, connect, or disconnect devices.

                                                     *:Android-emulator-start*
:Android emulator start
        Start the remembered AVD, or choose from an AVD-only picker when no AVD
        is selected. Completion occurs only after that exact AVD is online and
        boot-ready. An already-running exact AVD is adopted rather than started
        again, and another in-flight start for the same AVD is rejected. The
        operation is bounded and cancellable.

                                                      *:Android-emulator-stop*
:Android emulator stop
        Stop the exact remembered running emulator and wait until that identity
        disappears or its serial is proven to belong to another AVD. When the
        current selection is absent or physical, choose from a running-AVD-only
        picker. A remembered stopped AVD produces an error instead of stopping
        another one. When the stopped AVD was already selected, it remains
        selected by name and can be started again without another picker. This
        never stops a physical device.

:Android build
        Run the selected target's exact qualified assemble task. The configured
        runner owns task execution and live output. Recognized source errors
        are published through the configured problem sink after the task result
        is accepted. The native runner opens its root-owned output split without
        moving focus.

                                                     *:Android-gradle*
:Android gradle
        Discover registered task names and always open one flat `Gradle task`
        picker, including when the model contains only one task. Entries are
        sorted lexically and labeled with their exact qualified Gradle task ID.
        The picker does not show groups or descriptions because discovery reads
        `tasks.names` without realizing task objects.

        The returned raw ID must match an offered task. Workbench then performs
        ordinary discovery again, resolves that ID in the current complete
        snapshot, and fails as stale if the task disappeared. It authorizes
        project execution again immediately before invoking the configured
        runner with direct argv equivalent to
        `{ gradlew, '--console=plain', exact_task_id }` at the canonical root.
        No shell, target/device selection, ADB work, persistent task choice,
        additional arguments, or task-specific environment is involved.

        Recognized failures use the same configured problem sink as Build and
        Run; complete output remains in the configured runner. Success clears
        that root's prior Workbench problems. Cancellation, preflight failure,
        trust denial, a stale task, or a malformed runner result preserves the
        prior list. Cancelling the picker itself is quiet.

        The catalog contains names already registered in each project. Tasks
        synthesized only by a Gradle task rule are not registered names and do
        not appear, even though Gradle may accept them when invoked directly.
        On Gradle before 9.1, composite build paths are derived from public
        parent/include relationships; discovery fails closed when a nested or
        repeated include cannot be identified uniquely. Gradle 9.1 and newer
        use Gradle's public `buildPath`.

                                                     *:Android-output*
:Android output
        Reopen and focus the latest native Build, Run, or arbitrary Gradle-task
        output for the current canonical root. The buffer remains available
        after success or failure until another task for that root replaces it
        or Android Workbench shuts down. It never selects or replaces an
        unrelated buffer or window.

        This command applies only to the dependency-free native runner. A
        configured custom runner retains its own output and window policy.

:Android run
        Run the selected target's exact qualified install task with
        `ANDROID_SERIAL` scoped to the remembered online device, resolve its
        enabled MAIN/LAUNCHER activity, and launch it. A remembered stopped AVD
        is started and awaited first by default, without another picker. A
        disconnected remembered physical device produces an error; Workbench
        never silently chooses a replacement. When selected, the Overseer
        adapter streams live output in a non-focused dock; Android Workbench
        reports completion or failure through its notification port. A
        successful install clears prior Gradle errors before launcher resolution,
        so a later ADB-only failure does not leave stale compile locations.

:Android stop
        Force-stop the selected application on the remembered online device.
        It does not stop the emulator or disconnect a physical device.

:Android cancel
        Cancel the active build, run, arbitrary Gradle task, application-stop,
        emulator-start, or emulator-stop workflow for the current root. An
        accepted cancellation keeps the root's operation slot occupied until
        its current child terminates. If an adapter refuses cancellation, the
        workflow remains active and may still complete normally. Process-backed
        adapters are expected to terminate their child within a bounded grace
        period.

:Android logcat
        Start or reveal Logcat for the selected application and online device.
        The default presenter resolves the installed package UID, so the stream
        includes application subprocesses and survives application PID
        restarts. A shared Android UID can also include sibling packages.

:Android logcat stop
        Stop Logcat for the current project without cancelling Build or Run.

The native Logcat buffer retains a count- and byte-bounded local history and
contains only the currently visible records. When its last window is hidden,
capture continues while retained history moves into bounded owner-only
temporary files. Those files are unlinked immediately after opening and are
removed on restoration, stop, buffer wipeout, or shutdown. Showing the buffer
restores the newest retained history in order and reapplies its filters. If
private storage cannot be created, the presenter warns and keeps the same
bounded history in memory.

Handles created by one native presenter keep independent buffers, histories,
filters, and readers while sharing the bottom split created by that presenter.
Showing another hidden handle replaces only the buffer in that owned split.
If a handle is already visible in a manually arranged window, `show()` uses
that window instead. If the owned split is closed or changed to an unrelated
buffer, the next `show()` creates a new bottom split and leaves the unrelated
window untouched. A custom `ports.logcat` presenter owns its own window policy.

A window-local bar remains visible while following the stream. It shows the
application/device identity, stream state, minimum level, follow state, and the
most common controls. Press `?` for an owned popup containing every shortcut
and the current filter state.

The buffer-local controls are:

        ?       Show all Logcat shortcuts and current filter state.
        p       Pause or resume rendering; capture remains bounded and active.
        f       Toggle following the newest visible line.
        c       Clear only the local view. It never runs `adb logcat -c`.
        l       Choose the minimum visible level.
        t       Filter by tag text.
        /       Filter by message text.
        x       Reset level, tag, and text filters.
        <CR>/gf Open a resolvable Kotlin or Java stack frame.
        [f/]f   Move to the previous or next source frame.
        s       Stop this Logcat stream.
        q       Hide the view without stopping capture.

Inside shortcut help, `q`, `?`, or `<Esc>` closes only the popup.

Filters reproject retained history and do not restart ADB. Logcat frames are
navigable locations, not source diagnostics: the default presenter never
publishes them through |vim.diagnostic| and never opens Trouble automatically.

Commands have static completion. Completion never evaluates Gradle code,
queries ADB, or enumerates AVDs.

5. TRUST AND DISCOVERY                                *android-workbench-trust*

Android discovery and Gradle Build/Run/arbitrary-task execution evaluate
project-owned build logic. The default trust adapter calls |vim.secure.read()|
immediately before discovery and again immediately before actual Gradle
execution. Device and AVD discovery plus emulator start/stop use only Android
SDK/ADB tooling and never prompt for Gradle trust. Merely opening a project or
requesting status does not prompt, query ADB, or enumerate AVDs.

Discovery executes the project `gradlew` directly with a bundled, versioned
init script. It uses argv rather than a shell, disables configuration-on-demand
for the full-tree model, validates nonce-scoped bounded JSONL, and retains the
last complete snapshot after cancellation or failure.

Successful models carry a bounded content fingerprint covering Gradle scripts,
properties, version catalogs, wrapper inputs, Android manifests, buildSrc, and
included-build source. A later action lazily refreshes a changed model; there is
no watcher and no Gradle work merely to open a project. If the bounded scan
cannot produce a fingerprint, Workbench retains that complete model until an
explicit `:Android refresh` rather than repeatedly executing Gradle.

The tested compatibility floor is Gradle 7.3.3 with Android Gradle Plugin
7.1.3. Gradle 9 composite builds are supported. The current implementation
executes the Unix `gradlew`; `gradlew.bat` support is deliberately not claimed
yet.

Selections are stored per canonical root under `stdpath('state')` with private
directory/file permissions. Parallel worktrees therefore keep separate state.
AVD creation, deletion, wiping, cold-boot controls, snapshot management, SDK
installation, and an embedded emulator UI remain outside the plugin. Workbench
also does not read Android Studio's selected-device or emulator state.

Run `:checkhealth android_workbench` for local prerequisites. When the current
directory is inside a wrapper project, health requires `gradlew` to be a regular
executable file, matching Gradle discovery.
